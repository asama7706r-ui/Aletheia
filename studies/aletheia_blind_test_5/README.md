## The claim
Inside a "workshop" W of finite-dimensional real unital algebras, when a build asks for a kind the old kind cannot hold, the procedure:
- builds the new kind by the smallest relaxation, by containment, of a sealed list of old rules (q1-q14), and never relaxes the two protected rules q1 and q2;
- gives every judged unit its mark, with a proof for every forced fall;
- builds a witness for every branch it accepts, or says plainly that none was built (NO_WITNESS);
- branches when relaxations tie and states what decides between them, merging a false tie only by a checked translation;
- finds when a known kind suffices (KNOWN_SUFFICES), when a requested value is free (FREEDOM), and when no relaxation works (IMPOSSIBLE);
- does all this without silent collapse or silent choice.

The seven items are tested as one machine. Every statement is relative to W (protocol, Section 1).

## Layout
- `seed/`: the sealed tower (`seed_registry.json`, in description language v0.5), the meaning of each id (`seed_notes.md`; the procedure never reads it), its builder and its spot checks.
- `lang/`: the description language v0.5 (`SPEC_v0.5.md`) and its strict reader (`reader_v0.py`).
- `procedure/procedure_v5.py`: the procedure. It searches by rewriting systems and templates, with a limit of 3600 s of wall-clock time per world.
- `scorer/`: the independent reference (`ref_v5.py`, linear algebra on truncated ideals; it never imports the procedure), the exact certificate checker (`certs_v5.py`), the seven baselines (`baselines_v5.py`), the scorer (`score_v5.py`), the world validator (`validate_v5.py`) and the dev fingerprints.
- `tools/`: `hash_files.py` (file hashes, and the combined hash of a batch's worlds) and `make_packages.py` (the generator packages, made at sealing).
- `run/run_batches.py`: the harness that ran the procedure once on both batches, keeping the machine awake.
- `batch_A/`, `batch_B/`: the 30 worlds and the key of each batch, copied from the generators' packages.
- `results/`: the outputs, the reports, the scorer's printed text (`score_X.txt`), and the run logs and times.
- `audit/`: the audit, its correction, and the diagnostic scripts with their outputs.
- `dev/`: the dev set and development checks, excluded from the test: `make_dev.py` (22 dev worlds in `batch_dev/`), `test_certs.py`, `fuzz_compare.py`, `mutation_test.py`, the worked examples of the addendum, quick trial scripts (`try_*.py`), and the logs of the last full checks before sealing (`final_2026-10-23/`, `final_2026-10-23b/`).
- `argon_probe/`: the environment probe given to the batch-B generator before its real task.
- `GENERATOR_START.md` is the (Arabic) start message given to the generators; `GENERATOR_START_en.md` is its English translation.
- Not included: the generators' own working files (their builders, key verifiers, notes and logs), which stayed in their packages outside the lab.

## Reproduce the test
From this folder, with Python 3.12 and sympy 1.14 (the versions of the run):
```
python -I scorer/validate_v5.py batch_A
python -I scorer/score_v5.py batch_A results/outputs_A.json results/report_A_rerun.json
python -I procedure/procedure_v5.py run batch_A/worlds results/outputs_A_rerun.json
```
and the same for `batch_B`.
- **The validator** printed VALID for each batch in the generators' runs (audit, section 1).
- **The scorer** has no time limit and no randomness, so on the published outputs it is expected to reproduce `results/report_X.json` byte for byte. It took 830 s (A) and 127 s (B). It was not rerun for this publication.
- **The procedure** is not reproducible byte for byte. It stops on a wall-clock limit of 3600 s per world, and one world (A W-28) hit that limit in the run, so its output depends on the machine and its load. The run took 3984 s (A) and 29 s (B), alone on the machine. Compare a rerun's decisions with the published outputs, not its hash.
- The rerun names keep the published files intact; `run/run_batches.py` refuses to overwrite `results/outputs_X.json`.
