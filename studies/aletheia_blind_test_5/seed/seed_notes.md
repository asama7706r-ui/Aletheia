# Test 5 seed: what each id means, and where each rule comes from

`seed_registry.json` is the tower of test 5, written in description language v0.5 (`../lang/SPEC_v0.5.md`) and built by `make_seed.py`. Ids are neutral, so that names carry no meaning (test-4 decision R3). This file is for the world generators and for human review. The kernel's procedure never reads it.

Status: DRAFT, not sealed (2026-10-21; bounds added 2026-10-22). The content of the tower was reviewed and approved by the project owner: list v1 (Q10 page, 11.8, 2026-10-19), the complex list and the five v0.5 questions (v0.5 page, section 15.8, 2026-10-21). It will be sealed by SHA-256 together with the protocol and the code (test-5 draft, section 13, step 4), before any world exists. Until then `SEALED_HASHES.txt` does not exist, and the canonical SHA-256 printed by `check_seed.py` is the one to compare.

## The tower
| id | what it is |
|---|---|
| `f01` | the floor of the real numbers; its rules are list v1, version 1 |
| `k01` | the real numbers (over the reals, a single number) |
| `f02` | the floor of the complex numbers (depends on `f01`); its rules are list v1 without the order bundle |
| `k02` | the complex numbers (over the reals, two components) |
| `e1` | the generator of `k02`, the imaginary unit: `e1*e1 = -1` is the kind's relation |
| `f03` | a frame floor: "the elements act on a state"; it carries no kind |
| `t1` | the theorem of `f03`: composition of actions is associative |

A build in a world names `k01` or `k02` as its `origin`. Its role may use `e1` only when the origin is `k02`. It names `f03` in `frames` only when the law's text says that the new elements act on a state (test-5 draft, trap 10).

## The rules of f01 (list v1, Q10 page 11.8)
Every variable is declared `"new"`: when the kernel judges a rule on a candidate new kind, its variables range over the whole candidate.

| id | protected | meaning | sentences |
|---|---|---|---|
| q1 | yes | one is not zero | `1 != 0` |
| q2 | yes | the old numbers do not collapse, and their arithmetic does not change: 0, 1, +, the negative, ×, the inverse and the order keep their values among old numbers | keeps `0 1 + - * ^-1 >` |
| q3 | no | addition is associative | `(a + b) + c = a + (b + c)` |
| q4 | no | addition is commutative (provable from q3, q7-q11; Q10 11.4 item 2) | `a + b = b + a` |
| q5 | no | multiplication is associative | `(a*b)*c = a*(b*c)` |
| q6 | no | multiplication is commutative; its type-restricted parts (old with new, new with new) are generated by the procedure, not written | `a*b = b*a` |
| q7 | no | left distributivity | `a*(b + c) = a*b + a*c` |
| q8 | no | right distributivity (two separate sides, no bundle; Q10 11.6, 2c) | `(a + b)*c = a*c + b*c` |
| q9 | no | 0 is the identity of addition | `a + 0 = a` |
| q10 | no | 1 is the identity of multiplication | `1*a = a`, `a*1 = a` |
| q11 | no | every number has a negative, a named operation | `a + (-a) = 0` |
| q12 | no | no zero divisors | `a*b = 0 -> a = 0 \| b = 0` |
| q13 | no | the inverse is a named operation (total: `0^-1` has a value the list leaves free; Q10, D1) | `a != 0 -> a*a^-1 = 1`, `a != 0 -> a^-1*a = 1` |
| q14 | no | the order bundle (Q10 11.6, 2a): a strict total order, kept by sums, and a positive times a positive is positive | five sentences, see the file |

- q2 added the negative `-` on 2026-10-21, by the project owner's decision (v0.5 page 15.8, item 2): roles write `-1`, and it must stay the old -1.
- q14's last part is written "a positive times a positive is positive", which has no side of the product (v0.5 page 15.8, item 3). The list wrote the order with `<`; the language writes it with `>`, which only changes the direction.

## The rules of f02 (the complex list, test-5 draft decision 8)
The same ids and sentences as f01, q1 to q13, with no q14. Its q2 keeps `0 1 + - * ^-1` (no order: the complex numbers have none). `e1*e1 = -1` is the relation of `k02`, not a rule. It has no variables, so it is a fact about one old element, and q2 protects it whenever a kind is built over `k02` (v0.5 page 15.5, approved).

## The rule of f03 (the frame)
`t1`: `(a*b)*c = a*(b*c)`, protected: a theorem is never relaxed. For a kind whose elements act on a state, the product is composition, and applying three actions in turn does not depend on how they are grouped. Commutativity is not a frame theorem (rotations of space do not commute).

## Declared gaps (written before any world exists)
1. **The list is incomplete by nature** (the header of list v1): a rule absent from the list is neither checked nor counted, and every verdict is relative to list version 1.
2. **The completeness of the reals** cannot be written in v0.5, nor its shadow in sentences ("every positive number has a square root", "every polynomial of odd degree has a root"; Tarski). These facts are used by the kernel's checker over the reals, not written as rules.
3. **The proof of t1 is not written:** it needs a second sort (the state) and an operation that applies an action to a state, and v0.5 has neither. t1 is declared by the human seed, and the protocol of test 5 states that trap 10 rests on this declared theorem (project owner's decision, v0.5 page 15.8, item 5).
4. Not a gap but a freedom: q13 leaves `0^-1` free. `check_seed.py` passes with `0^-1 = 0` and with `0^-1 = 5`.

## Numbers fixed after development (2026-10-22)
By decision 4 of the test-5 draft, these bounds are declared before any search. Their values were proposed after development, and they are sealed with the seed and the protocol (protocol_v5.md, Section 2.1):
- **P1, the parts degree: not used.** By decision 16 of the draft (approved 2026-10-22), the only parts are the type-restricted copies of the rules (old or new variables). Other identities of the old kind are not generated in this test.
- **P2 = 4:** the longest product in a role, and the base word length of the searches.
- **P3 = 16:** the largest dimension over the reals of a witness table. Dirac's algebra, the largest dev case, has dimension 16. A branch with no witness is `NO_WITNESS`, which does not mean impossible.
- **S = 4:** the deepest nesting of case nodes in a refutation.
The world generators get the same numbers, so that each key is computed under the bounds the procedure uses.

## Checks
`check_seed.py` (exit 0 on 2026-10-21):
- the v0.5 reader accepts the seed;
- every sentence of f01 holds on the rationals with their order (19 sentences, 4849 assignments, twice), and every sentence of f02 holds on complex numbers with rational parts (14 sentences, 2289 assignments, twice);
- t1 holds on 2 x 2 rational matrices (512 assignments);
- `e1*e1 = -1` holds for `e1 = (0, 1)`;
- 17 deliberately miswritten sentences all break, among them `a*b = b*a` on the matrices.

These are spot checks over finite pools of exact numbers, not proofs. They guard the writing of the seed. A false sentence that no pool element can break (for example "no number squares to 2", over a pool of rationals) would pass them.
